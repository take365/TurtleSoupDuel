# Codex 進行手順（依頼テンプレ付き）

> TurtleSoupDuel（Next.js × NoSQL β）での実装を、**小さなスプリント**で安全に前進させるための順番と、コピペで使える**Codex CLI依頼テンプレ**のセットです。

---

## 0. 雛形 & 接続テスト

**ゴール**

* Next.js（App Router）初期化、Tailwind+shadcn導入
* Cassandra接続 `lib/cassandra.ts`
* `GET /api/health` が 200

**受入れ条件**

* Node runtimeで動作（Edge不可）
* `@datastax/cassandra-driver` を使用

**依頼テンプレ**

```text
目的: Next.js(App Router)の初期化とCassandra接続の土台を作成。
要件:
- Tailwind + shadcn/ui をセットアップ
- lib/cassandra.ts を作成（env: CASSANDRA_CONTACT_POINTS, CASSANDRA_DC, CASSANDRA_KEYSPACE, CASSANDRA_USER, CASSANDRA_PASS）
- Route Handler: GET /api/health → {ok:true, runtime:"node"}
- Next.jsの設定は Node.js runtime を明示（edge不可）
成果物: package.json, tailwind設定, lib/cassandra.ts, app/api/health/route.ts
```

## 1. 認証＆招待（最小フロー）

**ゴール**

* `POST /api/auth/signup`（招待+handle+password）
* `POST /api/auth/login`（httpOnly Cookieでセッション）
* CQL: `users_by_id`, `handle_to_user`（LWT）, `sessions_by_id`（TTL）, `invites_by_code`, `invite_slots`

**受入れ条件**

* 重複handleでsignup → エラー
* 使い切った招待 → signup不可
* Cookieベースでログイン継続（14日TTL想定）

**依頼テンプレ**

```text
目的: 招待コードベースのサインアップとログインを実装。
前提: Cassandra keyspaceあり。CQLは docs「TurtleSoupDuel_フロント＆DB方針（Next.js×NoSQLβ）」の定義に準拠。
要件:
- CQL: users_by_id, handle_to_user, sessions_by_id(TTL), invites_by_code, invite_slots を作成するmigrationスクリプト
- POST /api/auth/signup: 招待スロットを LWT で取得、handle を LWT で確保、Argon2idでpwハッシュ保存、セッション発行
- POST /api/auth/login: 認証後にhttpOnly Cookieでsession_id設定
- POST /api/auth/logout: Cookie無効化
- バリデーション: handle(3-32, 英数+_), password(>=8)
```

## 2. テーマ一覧(#3) と ゲーム画面(#2) 骨組み + SSEプロキシ

**ゴール**

* `/themes`：カード一覧（title/snippet/クリア/likesのダミー表示）
* `/play/[themeId]`：タイムライン＋入力欄（UIだけでもOK）
* FastAPIのSSEを Next.js の Route Handler で **プロキシ**
* CQL: `themes_by_id` と一覧API

**受入れ条件**

* `/themes` がSSRで描画、カードクリックで `/play/id` 遷移
* `/api/play/:id/stream` がSSEで受信（モック可）

**依頼テンプレ**

```text
目的: テーマ一覧/ゲーム画面の最小UIとSSEプロキシを実装。
要件:
- CQL: themes_by_id(theme_id, title, snippet)
- GET /api/themes: [{themeId,title,snippet,likes:0,cleared:false}]
- app/themes/page.tsx: SSRでカードグリッド
- app/play/[themeId]/page.tsx: タイムラインUI・入力欄・開始ボタン
- GET /api/play/[themeId]/stream: FastAPIのSSEをReadableStreamで中継（Node runtime）
```

## 3. 使用量メーター＆レート制御

**ゴール**

* CQL: `usage_total_by_user` / `usage_by_user_date`（counter）
* `GET /api/me/usage`（今日/総量）
* ヘッダーにProgress表示、閾値超過で送信ボタンdisable

**受入れ条件**

* API呼び出し時にcounter加算（モック値でも可）
* 今日/総量がUIに反映、閾値でUIブロック

**依頼テンプレ**

```text
目的: 使用量のカウンタとメーター表示を実装。
要件:
- CQL: usage_total_by_user, usage_by_user_date counters
- GET /api/me/usage → {today:{calls,pt,ot}, total:{calls,pt,ot}}
- 呼び出し共通ミドルウェア: しきい値超過時は429
- ヘッダーメーター: shadcn/ui Progress で today.calls/limit を表示
```

## 4. クリア・いいね・キャラ好感度

**ゴール**

* クリア登録 `INSERT ... IF NOT EXISTS`
* いいね/解除＋`theme_like_counts` counter
* 好感度 `affinity_by_user`（加算/減算API）
* `/themes` と `/play` UIに反映

**受入れ条件**

* 同テーマのクリア重複不可
* いいね二重押しで数が狂わない
* 好感度が0–100で変動

**依頼テンプレ**

```text
目的: テーマ進捗(クリア)といいね、好感度を実装。
要件:
- CQL: clears_by_user, likes_by_user, likes_by_theme, theme_like_counts, affinity_by_user
- POST /api/themes/:id/clear → 200 or 409
- POST /api/themes/:id/like /unlike → likes counter +1/-1
- POST /api/characters/:id/affinity {delta} → score 0..100でclamp
- UI: /themes と /play にクリア/いいね/好感度を反映
```

## 5. 投稿(#4)・管理(#1) の最小実装

**ゴール**

* ユーザ投稿テーマ：下書き/申請/公開/停止
* 管理：招待発行（回数/期限）、ユーザ凍結/解除

**受入れ条件**

* 必須未入力で申請不可、承認で公開
* 招待の残枠0でサインアップ不可
* 凍結ユーザはAPI 403

**依頼テンプレ**

```text
目的: ユーザ投稿と管理機能の最小実装。
要件:
- CQL: user_themes（status: draft|submitted|public|suspended）
- POST /api/user-themes (create/update/submit), /api/admin/user-themes/:id/approve
- /submit/theme, /my/themes ページ（RHF+Zod）
- /admin/invites: 発行(回数/期限)→ invite_slots を事前生成
- /admin/users: 凍結/解除 → 認証ミドルウェアで403
```

### 運用Tips

* 毎スプリントの依頼に **「CQLに準拠」「Node runtime明示」** を付記。
* ブランチを小刻みに（例: `feat/auth-invite`, `feat/themes-sse`, `feat/usage-meter`）。
* 受入れチェックをテンプレ末尾に残しておくと、Codex出力の品質が安定します。
