# TurtleSoupDuel 画面要件定義（Next.js × さくら NoSQL β）

**対象バージョン**：v0.1（最小実装）→ v0.2（管理/投稿拡張）
**前提**：フロントは Next.js（App Router, SSR+CSR, Tailwind+shadcn/ui）。DB は NoSQL β（Cassandra）。FastAPI はゲーム進行BFF。

---

## 1. 共通要件（UI/認証/配信/制限・NFR）

### 1.1 UI/UX

* **レイアウト**：デスクトップ優先（幅≥1024）。モバイルは後追い（主要動線のみ対応）。
* **ダーク/ライト**：ダーク標準、ユーザ切替を `localStorage` 持続。
* **コンポーネント**：shadcn/ui（Button, Card, Dialog, Tabs, DataTable, Toaster）。アイコンは lucide-react。
* **フィードバック**：主要操作はトースト表示（成功/警告/失敗）。長処理はスピナー＋キャンセル。

### 1.2 認証/権限

* **招待コード + ID/PW** サインアップ。ハンドル重複は禁止（LWT）。
* **セッション**：httpOnly Cookie。DBの `sessions_by_id` は TTL（14日）。
* **ロール**：`user/admin`。管理画面はサーバ側でガード。
* **アカウント凍結**：凍結時はログイン不可/全API 403。

### 1.3 配信/通信

* **SSE** によるストリーミング（チャット）。途中停止・再接続（カーソル/Last-Event-ID）。
* **タイムアウト**：SSEは 120秒無通信で再接続。RESTは 30秒。
* **エラー規約**：`{code, message, hint}` を返す。UIはメッセージ＋再試行導線。

### 1.4 レート/コスト制御

* **カウンタ**：合計/日次を counter テーブルで管理。閾値超過で 429（UIはボタンdisable）。
* **メーター**：ヘッダーに本日/総量をProgress表示。閾値に近づいたら警告色。

### 1.5 非機能（NFR）

* **パフォーマンス**：初回 TTFB < 1.5s（日本国内）、LCP < 2.5s（キャッシュ後）。
* **信頼性**：重要更新は LWT 採用（ハンドル、招待スロット、クリア重複防止、いいね重複）。
* **監査/ログ**：管理系操作（招待発行/凍結/権限変更）は操作ログを残す（アプリログ→将来別テーブル）。
* **テレメトリ**：主要イベント（ログイン、ゲーム開始/終了、クリア、いいね、トークン消費）を計測。

## 2. 画面別要件

### #1 ユーザ管理（一般/管理）

**Routes**：

* 一般：`/login`（ログイン） `/signup?code=`（招待サインアップ） `/settings`（APIキー・オートログイン）
* 管理：`/admin/invites`（招待発行） `/admin/users`（凍結/初期化） `/admin/limits`（上限）

**機能**：

* 招待でサインアップ：`code + handle + password`。招待スロットを **LWT** で1枠確保。
* ログイン/ログアウト/オートログイン（Cookie 継続）。
* パスワード初期化（管理者が一時PW発行→次回強制変更）。
* 使用量メーター（今日/総量）。
* 凍結/解除、招待コード発行（回数/期限指定）。

**入力/検証**：

* handle：英数と`_`、3–32文字、ユニーク（LWT）。
* password：8–128文字、簡易強度メーター表示。
* 招待：期限内・残枠>0 で有効。

**受け入れ条件（例）**：

* [ ] 同一 handle でサインアップ試行すると「使用中」エラー。
* [ ] 使い切った招待コードはサインアップ不可。
* [ ] 凍結ユーザは API が 403 を返す。

---

### #2 ゲーム（チャット）

**Route**：`/play/[themeId]`

**レイアウト**：

* 左ペイン：テーマタイトル/問題/クリア状態/いいね数。
* 中央：タイムライン（ユーザ/MC/対戦の吹き出し、ターン見出し、システムノート）。
* 右ペイン：キャラ選択（MC/対戦）、好感度、ターン数、残り質問数、使用量メーター。

**進行**：

* 開始 → ユーザ質問 → MC判定 → ユーザ最終解答 → MC判定 → 対戦“よいしょ” → 対戦質問 → MC判定 → 対戦最終解答 → MC判定 → 対戦“よいしょ” → ターンエンド。
* 勝者確定時：最終“よいしょ”→結果ダイアログ→クリア登録（`INSERT IF NOT EXISTS`）。

**操作**：

* 入力欄（質問/最終解答）。進行ボタン（開始/質問送信/解答送信/次のターン）。
* SSE停止/再開、ログ保存（将来）。

**状態/制約**：

* クリア済テーマの再プレイは確認ダイアログ。
* 閾値超過時、送信ボタン disabled（ガイド表示）。

**受け入れ条件**：

* [ ] ストリーム断後に再接続しても直前のメッセージから再開。
* [ ] 既クリアテーマで「開始」押下→確認→キャンセルで開始しない。
* [ ] クリア登録は重複しない（1ユーザ1テーマで一意）。

---

### #3 テーマ選択

**Route**：`/themes`

**表示**：

* カードグリッド：タイトル、問題冒頭（snippet）、クリアバッジ、いいね数、“いいね”チェック。
* ソート：デフォルト新着、人気順（いいね数）、クリア済み優先の切替。
* フィルタ：未クリアのみ/クリア済みのみ/全件。

**選択**：

* MCキャラ、対戦キャラの選択（プレビュー吹き出し）。
* 「開始」ボタン：未選択項目があればバリデーション表示。

**受け入れ条件**：

* [ ] いいね操作で即座に数が反映される（二重押し不可）。
* [ ] 未選択のまま開始を押すとエラーメッセージ。

---

### #4 テーマ登録（ユーザ投稿）

**Route**：`/submit/theme`（新規） `/my/themes`（自分の投稿一覧）

**入力**：

* タイトル（必須, 8–100）
* 質問（必須, 20–300）
* solution（必須, 100–2000）
* facts（0–20個, 各≤120）
* tags（0–10個, 英数/ハイフン）
* 紹介URL、匿名希望チェック

**機能**：

* **AIアドバイス**：下書きに対して推敲案を提示し、差分マージ（採用/破棄）。
* **下書き保存**（ローカル自動保存 + サーバ保存）
* **登録申請** → 管理ワークフロー（承認で公開）。
* **公開停止/再開**（自分の投稿に限る、管理者は全件可）。

**受け入れ条件**：

* [ ] 必須項目未入力で申請不可。
* [ ] 申請→`submitted`、承認→`public`。状態遷移が履歴に残る。

---

### #5 キャラクター登録

**Route**：`/submit/character`

**入力**：

* 名前、アバター複数（正方形推奨）、性格/口調のプリセット、プロンプト/制御JSON（テキストエリア）。

**機能**：

* **テストエリア**：サンプル質問→応答のプレビュー（トークン使用量表示）。
* **プリセット**：敬語/タメ口/熱血/クール など UI選択→内部JSONに反映。

**受け入れ条件**：

* [ ] JSON が不正な場合、保存不可（エラー箇所表示）。
* [ ] テスト実行で SSE が正常に完走する。

## 3. API/I-O 契約（フロント観点）

> 具体のエンドポイント名は実装時に確定。ここでは **入出力の骨子** を定義。

**認証**

* `POST /api/auth/signup`：{code, handle, password} → {sessionId}
* `POST /api/auth/login`：{handle, password} → {sessionId}
* `POST /api/auth/logout`：{} → 204

**メーター/プロフィール**

* `GET /api/me/usage` → {today:{calls,pt,ot}, total:{calls,pt,ot}}
* `GET /api/me` → {userId, handle, role, frozen}

**テーマ**

* `GET /api/themes` → \[{themeId, title, snippet, likes, cleared\:boolean}]
* `POST /api/themes/:id/like`（/unlike） → 204（カウンタ更新）

**クリア**

* `POST /api/themes/:id/clear` → 200 / 409（IF NOT EXISTS失敗）

**ゲーム/SSE**

* `GET /api/play/:id/stream`（SSE） → `event: message` data:{actor,kind,text,turn,phase}
* `POST /api/play/:id/user-question`：{text}
* `POST /api/play/:id/user-guess`：{text}

**投稿/キャラ**

* `POST /api/user-themes`（下書き/申請） / `GET /api/user-themes`
* `POST /api/characters` / `GET /api/characters`

## 4. 受け入れテスト & 導入段階

**Smoke（v0.1）**

* [ ] 招待→サインアップ→ログイン→/themes 表示→/play 開始→1ターン進行→メーター加算。
* [ ] クリア登録が二重にならない（同一ユーザ/テーマ）。
* [ ] いいね/解除が二重にならない＆数が一致。

**v0.2（管理/投稿）**

* [ ] 招待発行（回数/期限）→残枠0で登録不可。
* [ ] 投稿→申請→承認→公開停止/再開が状態遷移として記録。
