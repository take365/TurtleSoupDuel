# うみがめのスープ（AI対戦）設計書 v0.1

## 0. 目的と前提

* **目的**: AIが進行役を務め、ユーザとAI対戦者が交互に質問/解答する水平思考クイズ（うみがめのスープ）を最小構成で動かす。
* **前提**:

  * バックエンド: **Python + REST API**（FastAPI優先、Flask代替可）
  * フロント: まずはシンプルなテンプレ（静的HTML＋Fetch/axios）
  * DB: **未使用（当面はメモリ管理）**。テーマはJSONファイル群で供給。
  * モデル選択: 進行LLMは**環境変数で選択**、AI対戦者のLLMは**テーマ選択画面で選択**。
  * プロンプト: 進行用/対戦者用を**別ファイル**で管理。

---

## 1. 全体アーキテクチャ

```
[Front]  ── REST ──>  [API Server(FastAPI)]  ──>  [LLM Provider(進行役)]
                              │
                              ├─> [LLM Provider(AI対戦者)]
                              │
                              └─> [Theme Files(JSON folder)]
```

* **セッション/ゲーム**: v0.1は**単一ゲーム/単一ユーザ**前提。GameManagerで1インスタンス管理。
* **状態保管**: サーバメモリ上の`GameState`に集約。
* **テーマ**: `themes/*.json`に格納（スキーマ定義は後述）。

---

## 2. ゲームルール/フロー（v0.1）

* ターン定義（1ターン）:

  1. ユーザが**Yes/No質問**（またはパス）。
  2. 進行LLMが**判定**: `YES|NO|おしい|不適切` + 任意の短い補足。
  3. ユーザが**最終解答**（またはパス）。
  4. 進行LLMが**正解/不正解**を判定（不正解時はヒント出さない）。
  5. AI対戦者が**Yes/No質問**を生成。
  6. 進行LLMが**判定**（上と同様）。
  7. AI対戦者が**最終解答**を生成（またはパス）。
  8. 進行LLMが**正解/不正解**を判定。
  9. 次ターンへ。
* **勝敗**: 先に正解した側が勝利（引き分けなし）。
* **ヒント/不適切**判定は進行LLMのプロンプトに委譲。

### 状態マシン（簡易）

```
IDLE -> THEME_SELECTED -> IN_TURN
IN_TURN: USER_Q -> MC_A -> USER_GUESS -> MC_JUDGE -> AI_Q -> MC_A -> AI_GUESS -> MC_JUDGE -> (WIN|IN_TURN)
WIN -> FINISHED
```

## 3. テーマファイル仕様

* フォルダ: `themes/`
* 1ファイル = 1テーマ。

```json
{
  "id": "turtle-0001",
  "title": "うみがめのスープ",
  "question": "男はレストランで……なぜ？",
  "solution": "(完全解説テキスト)",
  "facts": [
    "スープは本物のうみがめである",
    "男は過去の遭難経験がある"
  ],
  "tags": ["classic", "hard"],
  "lang": "ja"
}
```

* **必須**: `id`, `title`, `question`, `solution`
* **任意**: `facts`, `tags`, `lang`

## 4. REST API 設計（v0.1）

### ベース

* `BasePath: /api/v1`
* `Content-Type: application/json`

### 4.1 テーマ

* **GET** `/themes`

  * 概要: テーマ一覧取得
  * Res: `[{ id, title, tags, lang }]`
* **GET** `/themes/{theme_id}`

  * 概要: テーマ詳細取得（`solution`はサーバ内で保持し、原則返さない。進行LLMへの内部入力にのみ使用）
  * Res: `{ id, title, question, tags, lang }`

### 4.2 ゲームの開始/設定

* **POST** `/game/start`

  * Req: `{ theme_id: string, ai_model: string }`
  * Res: `{ game_status: "IN_TURN", current_turn: 1, player: "user" }`
  * 挙動: `GameState`を初期化し、選択テーマをロード。AI対戦者モデルをセット。

### 4.3 ユーザの質問/回答

* **POST** `/game/user/question`

  * Req: `{ text: string | null, pass?: boolean }`
  * Res: `{ judge: "YES"|"NO"|"おしい"|"不適切", note?: string }`
* **POST** `/game/user/guess`

  * Req: `{ text: string | null, pass?: boolean }`
  * Res: `{ result: "CORRECT"|"WRONG", is_win: boolean }`

### 4.4 AI対戦者の質問/回答（分離）

* **POST** `/game/ai/question`

  * Req: `{}`（サーバ側で履歴・テーマを参照し質問を生成）
  * Res: `{ text: string, judge: "YES"|"NO"|"おしい"|"不適切", note?: string }`
* **POST** `/game/ai/guess`

  * Req: `{}`
  * Res: `{ text: string, result: "CORRECT"|"WRONG", is_win: boolean }`

### 4.5 ターン制御/状態参照

* **POST** `/game/next`

  * 概要: ターンを次のフェーズに進める（ガード付き）
  * Res: `{ game_status, current_turn, phase, last_events: [...] }`
* **GET** `/game/state`

  * 概要: 現在の状態/履歴の簡易スナップショット
  * Res: `{ theme_id, turn, phase, history: { user_qas: [...], ai_qas: [...] }, winner?: "user"|"ai" }`

> 注: v0.1は単一ゲーム前提のため`game_id`は省略。将来的に`/:game_id/`に拡張可能な形で内部実装。

## 5. データモデル（メモリ内）

```ts
// 擬似TypeScript表記
type Judge = "YES" | "NO" | "おしい" | "不適切";

type QA = {
  actor: "user" | "ai",
  kind: "question" | "guess",
  text: string | null,
  pass: boolean,
  judge?: Judge,
  note?: string,
  result?: "CORRECT" | "WRONG"
};

type Theme = {
  id: string; title: string; question: string; solution: string;
  facts?: string[]; tags?: string[]; lang?: string;
};

type GameState = {
  status: "IDLE" | "THEME_SELECTED" | "IN_TURN" | "WIN" | "FINISHED";
  theme?: Theme;
  turn: number;
  phase: "USER_Q" | "MC_A" | "USER_GUESS" | "MC_JUDGE" | "AI_Q" | "AI_MC_A" | "AI_GUESS" | "AI_MC_JUDGE";
  history: QA[];
  winner?: "user" | "ai";
  models: { mc_model: string; ai_model: string; };
};
```

## 6. LLM 抽象化

* **LLMProvider**（Strategy パターン）

  * `ask_mc_judge(theme, history, question)` → `{ judge, note }`
  * `ask_mc_verify(theme, guess)` → `{ result }`
  * `ai_generate_question(theme, history)` → `{ text }`
  * `ai_generate_guess(theme, history)` → `{ text }`
* 実装例: `providers/openai_mc.py`, `providers/openai_ai.py`, 将来 `providers/local_xx.py` 追加。
* **モデル切替**:

  * 進行役: `.env`の`MC_MODEL`, `MC_PROVIDER`
  * AI対戦者: `/game/start`の`ai_model`で指定

## 7. プロンプト設計（外部ファイル）

```
prompts/
  mc/
    judge_question.jinja   # Yes/No/おしい/不適切 + note（日本語出力）
    verify_answer.jinja    # 正誤判定（理由は内部のみに使用）
  ai/
    gen_question.jinja     # 履歴+テーマから有効なYes/No質問を1つ生成
    gen_guess.jinja        # 最終解答（過度な長文回避）
```

* **方針**:

  * 進行役: ルール厳守、ヒント条件、メタ情報の非開示、**solution/facts**は外部へ出さない。
  * 対戦者: 履歴の網羅性/情報利得を意識した質問を促す（重複回避）。

## 9. エラーハンドリング/ガード

* フェーズ不一致のAPI呼出: `409 Conflict` + `{ error: "invalid_phase" }`
* 必須パラメータ欠落: `400 Bad Request`
* テーマ未ロード: `400` or `404`
* LLM失敗: `502 Bad Gateway`（タイムアウト/レートなど）

## 付録B: 進行/対戦のプロンプト要点

* **進行（judge\_question）**:

  * ルール: Yes/No/おしい/不適切 のみ。過度なネタバレ禁止。必要に応じ短いnote。
  * 禁止: solutionの直接露出。
* **進行（verify\_answer）**:

  * ルール: 正解/不正解。理由はサーバ内ログ向けのみに返す。
* **AI対戦（gen\_question/guess）**:

  * 目的: 情報利得最大化、重複回避、事実網羅、ターン短縮。
